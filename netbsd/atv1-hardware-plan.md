# NetBSD 11.1/i386 on the first-generation Apple TV

Use the tested ATV1sm → rEFInd → NetBSD IA32 EFI path. Boot the next hardware test from USB with a full stock GENERIC userland and kernel, a writable disposable USB root, and Ethernet reporting. Keep the current INSTALL RAM image available for recovery. Test the hardware profile before provisioning the internal disk.

## CPU, power and build settings

The report shows one 1 GHz Intel CPU, ID 0x6d8, package 0/core 0/SMT 0. Interpreting “smp1” as SMP with one logical processor, keep the release kernel. Confirm with `cpuctl list`, `cpuctl identify 0` and `sysctl hw.ncpu`. An SMP kernel can run on this machine, but a second worker cannot create a second hardware thread. [cpuctl](https://man.netbsd.org/cpuctl.8)

acpicpu already advertises **600, 800 and 1000 MHz**, C1/C2/C3 idle states and eight throttling levels (report lines 151–165). Collect `sysctl machdep.cpu.frequency hw.acpi.cpu`, `vmstat -e`, and `envstat`. The ACPI figures are firmware estimates. Measure whole-device power at the outlet if available. NetBSD documents C1 as the default usable ACPI idle state. Keep stock idle and throttle policy. For an interactive frequency test, record the original target, set one advertised value with e.g. `sysctl -w machdep.cpu.frequency.target=600`, read `.current` under load, repeat for 800 and 1000, then restore the original target. If the nodes are absent or the clock fails to change, record it and skip persistence. Compare fixed performance, low-power and optional demand scaling via pkgsrc estd only after manual transitions and post-idle Ethernet work. [acpicpu](https://man.netbsd.org/acpicpu.4) · [estd](https://cdn.netbsd.org/pub/pkgsrc/current/pkgsrc/sysutils/estd/index.html)

Start with release binaries. With 252 MB detected RAM, prefer cross-building on mbp and limiting background services. Benchmark the same representative userspace workload three times at the same clock with identical input and optimization level, first stock, then with `-mtune=pentium-m`. Record elapsed time, peak RSS and binary size. Consider `-march=pentium-m` only for an ATV-specific binary after checking CPUID. Keep a tuned binary only if its improvement exceeds run-to-run variation and output matches. Avoid host-native flags during cross-builds and preserve the kernel's architecture and floating-point conventions. [GCC x86 options](https://gcc.gnu.org/onlinedocs/gcc/x86-Options.html)

## Firmware decision

The verified USB boot requires its existing Apple diagnostic/ATV1sm EFI inputs. Preserve those known versions and hashes. The working genfb, ATA, USB, Ethernet and CPU paths need no additional device blobs. NetBSD bwi requests its v3 firmware when bringing up a supported interface. This unit fails earlier in PHY attachment. Installing a Broadcom v3 or Linux b43 archive cannot supply the missing N-PHY driver code. Linux lists this PCI ID as partially supported by b43. No additional firmware package was identified for installation. For a future Nouveau or replacement Wi-Fi test, capture any firmware request verbatim, match it to the release driver and exact device, then verify provenance, license and checksum before adding it to that image. [NetBSD bwi](https://man.netbsd.org/bwi.4) · [Linux wireless device table](https://wireless.docs.kernel.org/en/latest/en/users/drivers/b43.html)

## Execution order and pass criteria

1. **Build one diagnostic USB.** Keep the timed default on native EFI with Nouveau disabled. Include GENERIC, matching base/etc/modules, a persistent USB root and the Ethernet reporter. Add an optional GENERIC entry allowing Nouveau. Provide headless selection via a one-boot configuration change on the USB and verify how to restore the default on mbp. Exercise both configurations in QEMU for packaging, then cold-boot the default on the ATV.
2. **Collect one hardware baseline.** Save dmesg, drvctl tree, pcictl PCI inventory, usbdevs -v, modstat, cpuctl output, CPU sysctls, envstat, audiocfg list, ifconfig -a, swapctl -lk and mount output to USB and mbp. Record missing tools or nodes individually. Confirm GENERIC boots from USB, internal wd0 is identifiable, and the router receives DHCP option 12 with value atv. Capture DHCP Discover/Request at the server or on a visible LAN segment. A static TCP report proves only transport.
3. **Exercise power and peripherals in the same boot.** Run repeat idle-to-burst transfers and compare checksums, interface errors and elapsed time before/after each CPU setting. Exercise audio, keyboard and IR as above. Keep a setting only when the result is repeatable. Perform the optional Nouveau test last. Record network reachability, nouveau attachment or firmware errors, mode and physical signal separately. An HDMI image alone does not establish acceleration. Restore the baseline entry after the test.
4. **Prepare the internal layout on a disposable disk first.** Use the proven ESP-first GPT entry order and Apple recovery type, with distinct names, a NetBSD swap wedge named atv-swap and remaining space in atv-root. Allocate **1 GiB swap** (2,097,152 sectors of 512 bytes). This is about four times detected RAM and leaves most of the 40 GB disk for files. The existing partition named swap has 1,937,500 sectors (about 946 MiB) and is reported as unknown type. Create a native NetBSD swap wedge for the new install. Put `NAME=atv-swap none swap sw 0 0` in fstab and verify `swapctl -lk` shows 1,048,576 KiB after cold boot. Measure peak usage and paging with `swapctl -sk` and `vmstat 1` during the intended workload. Increase to 2 GiB if a necessary workload exhausts swap; sustained paging on this PATA disk is a reason to reduce concurrency or build on mbp. [fstab](https://man.netbsd.org/fstab.5) · [swapctl](https://man.netbsd.org/swapctl.8)
5. **Qualify unattended installation.** In the VM verify the target identity guard, contents of both boot partitions, root, swap, persistent hostname and DHCP. Reboot with USB still inserted and verify completed disks are skipped. Then verify cold boot with USB removed and a second network report identifying the installed root, hostname, address and active swap. Perform the same sequence on the physical internal disk after VM acceptance. A durable install-complete file on USB and a separate installed-system ready report on mbp distinguish the two milestones.
